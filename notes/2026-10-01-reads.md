## Wallets and SDKs

- **Nautilus does not avoid address reuse by default and sends change to address index 0.**
  `nautls/nautilus-wallet`, `src/stores/walletStore.ts`: default settings `avoidAddressReuse: false`,
  `defaultChangeIndex: 0` (lines 99-101); change address selection at lines 266-268 picks an unused address only when
  `avoidAddressReuse` is set, otherwise the address at `defaultChangeIndex`.
- **Nautilus recognises P2SH outputs for display but builds P2PK spends.** GitHub code search for `p2sh` in that
  repository: `src/types/internal.ts`, `src/components/transaction/TransactionSign.vue`,
  `src/chains/ergo/transaction/interpreter/outputInterpreter.ts` (display and typing); the builder
  (`src/chains/ergo/transaction/builder.ts`) and prover (`prover.ts`) have no P2SH path. Weak zero: a search, not a
  full read of the wallet.
- **sigma-rust parses P2SH addresses; no P2SH spending path found.** `ergotree-ir/src/chain/address.rs` has
  `Address::P2SH([u8; 24])` and recreates it from a tree; GitHub code search for `DeserializeContext` under
  `ergo-lib` returns 0 files, `p2sh` returns only `ergo-lib/CHANGELOG.md`. Weak zero.
- **Fleet's transaction builder accepts context extensions.** `fleet-sdk/fleet`,
  `packages/core/src/models/ergoUnsignedInput.ts`: `setContextExtension(extension)` (and the deprecated
  `setContextVars`, line 49). A P2SH or WOTS spend needs exactly that. No P2SH-specific code found (`P2SH` appears in
  address models and test vectors only).
- **The mobile wallet (ergo-wallet-app) has multi-address screens; no reuse-avoidance setting found by search.**
  Weak zero.
- **No P2SH boxes exist on chain at height 753,934** is a measurement: `q1/out/by_category.csv`.

## Protocol facts read from source or official text

- **A P2PK address is the compressed public key.** `sigmastate-interpreter`,
  `data/shared/src/main/scala/org/ergoplatform/ErgoAddress.scala`, `class P2PKAddress`: `contentBytes = pubkeyBytes`.
  Executed check in `SCOPE.md` (decoding the documented mainnet address).
- **P2SH stores a 24-byte Blake2b256 hash and deserializes the script from context variable 126 at spend.** Same
  file, `class Pay2SHAddress.script`: `EQ(Slice(CalcBlake2b256(GetVarByteArray(scriptId)), 0, 24), scriptHash)`
  AND `DeserializeContext(scriptId, SSigmaProp)`, with `scriptId = 126`.
- **Fixed per-transaction cost.** `ergoplatform/ergo`,
  `ergo-core/src/main/scala/org/ergoplatform/modifiers/mempool/ErgoTransaction.scala` lines 374-378:
  `initialCost = interpreterInitCost + inputs x inputCost + dataInputs x dataInputCost + outputs x outputCost`;
  `interpreterInitCost = 10000` in `sigmastate-interpreter`
  `interpreter/shared/src/main/scala/sigmastate/interpreter/Interpreter.scala` line 514. Confirmed by the devnet
  residuals in `q2/devnet/README.md` (12,200 on every WOTS run; 16,300 on the 3-in/3-out wallet transaction).
- **Mainnet parameters** `inputCost 2407`, `outputCost 298`, `maxBlockCost 8001091`, `maxBlockSize 1271009`:
  `https://node.ergo.watch/info`, parameters stamped at height 1,885,184 (`LITERATURE.md`, cost-limits section).
- **Miner-votable parameters and steps.** `ergo-core/src/main/scala/org/ergoplatform/settings/Parameters.scala`:
  vote ids 1-9 (storage fee factor, min value per byte, max block size, max block cost, token access cost, input cost,
  data input cost, output cost, sub-blocks per block). `stepsTable` lists fixed steps only for ids 1, 2 and 9; the
  others move by `currentValue / 100` per epoch (`updateParams`), i.e. about 1% per 1,024-block epoch. `maxValues`
  has no entry for block cost or block size.
- **Sub-blocks parameter.** Same file: `SubblocksPerBlockIncrease = 9`, `SubblocksPerBlockDefault = 30`, min 2,
  max 2048, inserted into the table "on next epoch after block version v4 (protocol v6) activation". 30 per
  120-second block is 4 seconds, a derivation. The 6.0.6 node's `/info` on the devnet shows `subblocksPerBlock: 30`
  (`q2/devnet/README.md`).
- **Soft-fork activation rule.** Ergo forum, "6.0 Soft-Fork Proposal",
  `https://www.ergoforum.org/t/6-0-soft-fork-proposal/5005`: "90+% of hashrate support over 32 epochs 1024 blocks
  each (~1.5 months)"; old nodes "skipping scripts with new features". Docs page
  `https://docs.ergoplatform.com/dev/protocol/sigma-6/` (marked 2026-09-08) says 6.0 activated on mainnet in
  October 2025 (`LITERATURE.md`, Q3).

## Derivations used in the draft

- **Hashing share of the WOTS n=32 w=16 script cost, about 7%.** Worst-case message: 64 message chains x 15 hashes
  plus 30 checksum-chain hashes = 990 Blake2b256 calls on 32 bytes; `CalcBlake2b256` costs JIT 20 + 7 per 128-byte
  chunk = 27 JIT = 2.7 block units each (`LITERATURE.md`, cost-limits section; `trees.scala`), so about 2,670; plus
  the 2,144-byte public-key hash (20 + 7 x 17 = 139 JIT = 13.9) and the message hash. About 2,700 of the measured
  39,077 worst-case cost, 6.9%. Not measured by swapping the hash out; a follow-up.
  **Measured since** (branch measure-2, `q2/hash-share`, table in `q2/README.md` "Hashing versus interpretation"):
  on `wots-constant.es` hashing is 2,692 of 38,890 (0.0692) at n=32 w=16 and 22,737 of 242,822 (0.0936) at n=32 w=256.
- **A native verifier's node cost, roughly 15,700.** 13,003 fixed + about 2,700 of hashing, if interpretation
  overhead went to zero. Against `proveDlog`'s 13,406 that is within about 20%. An estimate, not a measurement.
- **Per-block capacities.** `q2/RESULT.md`, corrected table. Size-bound figures there use the harness transaction
  sizes (5,175 bytes for WOTS n=32 w=16, one output); the executed two-output devnet spend is 4,488 bytes, which gives
  1,271,009 / 4,488 = 283 per block size-bound. Cost-bound at 153 either way.
- **Height 753,934 is mid-2022.** From 2-minute blocks since the July 2019 genesis: 753,934 x 2 min = about 2.87
  years, i.e. around May 2022. Approximate.
