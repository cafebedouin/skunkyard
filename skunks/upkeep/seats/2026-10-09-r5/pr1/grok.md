## Defects

**1. Medium. Block cost can be the greater of two terms the node adds.** Verified: `Upkeep.member` charges `math.max(signed.getCost, accounted)` (`new/app/transactions/upkeep/Upkeep.scala:71-77`). `accountedCost` is defined as the charge before any script runs: interpreter init, plus per input, data input, output, and `2 * tokenEntries * tokenAccessCost` (`Upkeep.scala:32-44`). The rent source states that the node adds that structural term before validation and that script cost is separate, and its unsigned estimate adds them (`context/app/transactions/rent/StorageRent.scala:548-562`). The package admits on the cost `member` stored (`context/app/mining/CandidateBuilder.scala:561-564`, `context/app/transactions/candidate/CandidateBundle.scala:110-116`). Upkeep's own cap is `maxCost = 1000000` (`new/conf/application.conf:254`) inside a package share of half the block (`CandidateConfig.scala:58`).

Inferred, because `SignedTransaction.getCost` is not in this tree: the prover cost is the script reduction, as the rent comment describes a reduction cost that exists only once a script runs. On that reading, a beat whose script cost and structural cost are both positive is stored as the larger one. The node's charge is the sum. One beat stays far under `maxBlockCost`, so the node check accepts it (`UpkeepSource.scala:318-329` only drops a check failure). A full share, plus genesis and the other sources, can cross the block limit. The whole inserted package is then refused, which is the failure this PR is trying to narrow.

Also verified, and independent of that inference: the token count passed to `accountedCost` is `box.tokens.size` plus output token counts (`Upkeep.scala:73-74`). That is the one box the job was asked to advance. A direct `UpkeepJob` with further inputs that carry tokens omits those entries. Heartbeat has a single input (`ScriptJob.scala:172-173`), so the shipped job does not hit this.

Fix: treat the structural term and the script term as a sum, after confirming whether `getCost` already includes interpreter init. Pin `Upkeep.member` of one signed heartbeat against that sum. Counting `2 * entries` overstates when one id is repeated (`Upkeep.scala:36-39`); that direction is safe.

**2. Low. A build whose height was dropped still records holds.** Verified: `advance` sends `Spent`, `Refused`, and `Exhausted` from the worker before it returns (`UpkeepSource.scala:242`, `279-280`). `CandidatePreparation.drop` forgets the attempt and does not cancel the `Future` (`context/app/transactions/candidate/CandidatePreparation.scala:107-110`). The completion is ignored if the attempt no longer matches (`CandidatePreparation.scala:60-63`); the hold messages are not. A height dropped during signing or the node check can sit those boxes out for `retryAfterScans` passes, or hold them as unable to pay. Fix: put the attempt id on those messages and ignore them unless that attempt is still current.

**3. Low. Observe mode skips a height while the previous task is running.** Verified: `observe` starts work only when `blockHeight > observedThrough && !observing` (`UpkeepSource.scala:203-204`). A prepare and a request that both arrive before `Observed` (`UpkeepSource.scala:176`) do not record that height. The next height is watched; the skipped one is not. No transaction is offered in this mode. Fix: remember the skipped height and start it when `observing` clears, or allow one queued height.

### Checked, no concern

**Spending the wallet, or any box the job did not find.** Heartbeat discovery keeps a box only when its tree is the pinned contract, `maintains` accepts it, and it is not re-emission-blocked (`ScriptJob.scala:108-122`, `HeartbeatJob.scala:106-116`). `ScriptJob.signed` spends that box alone, with an empty prover (`ScriptJob.scala:172-179`). The source then refuses an input absent from the job's discovered set or from this build's read-back, and an input whose tree is in `signableTrees ++ rewardTrees.keySet` (`UpkeepSource.scala:377-388`). The actor spec covers a box at `wallet.contract.ergoTreeHex` (`UpkeepSourceSpec.scala:387-395`). `NodeWallet` is not in the slice; the reward-tree key format is inferred to match the node hex because that wallet-contract spec is written against the real wallet type. A heartbeat box is not a reward box anyway.

**A direct `UpkeepJob` and fees.** The source does not check fee outputs or where value goes. `UpkeepJob.scala:16-21` says so and leaves it to review. No such job is registered. Not a spend of the wallet on the shipped path.

**Refused by the node: height.** The preheader set before `buildTx` carries only `bc.height` (`ScriptJob.scala:177`). `buildTx` reuses that builder; the probe builder runs only when an input's creation height is above the context tip (`TxBuilder.scala:91-99`). Discovered inputs are confirmed, so the probe does not replace the preheader. DueJob reads `HEIGHT` and not miner key, votes, or timestamp (`DueJob.ergo:60`, `63-64`). A check at the wrong next height is dropped and not remembered (`UpkeepSource.scala:311-316`).

**Minimum value per byte.** `ScriptJob.minimumValue` prices a full input serialization, transaction reference included (`ScriptJob.scala:147-149`), the same bytes rent uses (`StorageRent.scala:514-517`). Heartbeat measures the successor at full value, pays `min(tip, value - floor)`, and either leaves a tip that cannot pay for its own box in the successor (`minTip == 0`) or declines (`minTip > 0`) (`HeartbeatJob.scala:54-70`). Value VLQ shrinks or stays when value falls, so that floor is high, not low.

**Tokens and EIP-27.** The successor copies `box.tokens` (`HeartbeatJob.scala:74-76`). The script requires `successor.tokens == SELF.tokens` (`DueJob.ergo:62`). On mainnet, discovery skips the proxy script and boxes holding the re-emission token, re-emission NFT, or emission NFT (`ScriptJob.scala:112`, `StorageRent.scala:97-112`). `Eip27Adjustment` is not in the slice. `TxBuilder.buildTx` always calls it (`TxBuilder.scala:66`). `HeartbeatJobSpec` and `ScriptJobSpec` expect two outputs on the mocked mainnet context (`HeartbeatJobSpec.scala:156`, `ScriptJobSpec.scala:218`). I did not execute them. A normal beat is not expected to grow a re-emission output.

**Two DueJob boxes and `OUTPUTS(0)`.** `onlyOne` is `INPUTS(0).id == SELF.id` (`DueJob.ergo:59`). The second such input fails its own script, so two boxes cannot share one successor. `DueJobSpec` builds that transaction and expects a signing refusal (`DueJobSpec.scala:211-220`).

**Creator locks.** These match the header, not an extra trap: non-positive period or negative tip (`DueJob.ergo:58`), a missing or wrong-typed register (`DueJob.ergo:29-30`, `54-56`), no exit (`DueJob.ergo:32-39`), and `R4 + R5` in `Long` so a sum past `Int.MaxValue` is never due (`DueJob.ergo:60`). The Scala reader uses the same `Long` sum (`HeartbeatJob.scala:123-125`).

**Actor versus build thread.** `offered()` is taken on the actor thread and closed over (`UpkeepSource.scala:180-195`). The worker does not touch `Memory`; it sends messages. `Memory`'s get-then-set is safe on the actor thread (`UpkeepSource.scala:476-479`, `504-530`). `lastAdmitted` is atomic and only affects a log line (`UpkeepSource.scala:83`, `293`). One build per height; a dropped attempt cannot answer the next (`CandidatePreparation.scala:85-96`). Scan and build can overlap on the polling pool; scan only reads `exhaustedIds`.

**Many boxes.** A script job reads at most 1,000 indexed boxes (`ScriptJob.scala:132-133`, `194`) plus configured ids, which validation caps at `min(maxBoxesPerJob, 256)` (`UpkeepConfig.scala:133`, `185-189`). The tracking cap keeps listed ids plus `maxBoxesPerJob` of the rest (`UpkeepSource.scala:428-434`). Read-back chunks those ids by 256 with no further call cap (`UpkeepSource.scala:232-233`, `459-460`). At the validation maximum that is 4,352 ids, 17 calls, for one job. Defaults are 256 tracked plus up to 256 configured. Signing stops after 16 refusals or 16 signed-but-unfitted successors (`UpkeepSource.scala:256-270`, `450-457`). The one-output floor (`Upkeep.scala:52-54`) can sign a two-output beat and then defer it; admission uses the measured size and `member`'s cost, and the deferral cap bounds that work.

## Tests

`due: a box whose R4 + R5 passes Int.MaxValue is not due` (`DueJobSpec.scala:145-154`) does not show that the comparison is false. The comment above it (`DueJobSpec.scala:140-143`) says an `Int` overflow would fail the script the same way. The contract text does use `Long` (`DueJob.ergo:60`); this property does not distinguish the two.

The most important missing test is `Upkeep.member` on one signed heartbeat: record `getCost`, the structural term, and their sum, and assert the stored cost is what the node adds to the block. `UpkeepSpec` checks the structural formula against `ErgoInterpreter.interpreterInitCost` and `ErgoBoxAssetExtractor` (`UpkeepSpec.scala:51-107`) and never against a signed DueJob transaction. The actor specs sign `FakeJob` with the wallet prover and no preheader (`FakeJob.scala:80-81`), so they do not lock height pinning either. `HeartbeatJobSpec` does, indirectly: a successor stamped at `ctx.getHeight + 1` signs (`HeartbeatJobSpec.scala:148-156`), which requires `HEIGHT` to be that height during reduction.

The other spec names I read match what they assert, including the wallet refusal, refresh served from the prepared set, observe-once-per-height, `verifyWithNode` off, drop, restart memory, share, rotation, and the 16-refusal cap.

## Design

Enforce fee zero, exact value, and the output whitelist in the source for every job. `ScriptJob` already does this, and the trait tells reviewers to do it by hand (`UpkeepJob.scala:16-21`). The extension point is the reason to have the source check.

Cap `discover()`'s returned list at the tracking cap before `found.toSet` (`UpkeepSource.scala:428-434`). A script job is bounded; a direct job is not, and `passed(known)` retains every id that pass found (`UpkeepSource.scala:118`).

Keep the 16-deferral cap. Teaching the floor about a two-output beat would avoid some signing and is not required for correctness.
