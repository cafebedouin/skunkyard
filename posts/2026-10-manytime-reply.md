One quantum-safe address that can be spent many times, with the chain refusing a reused or skipped-backwards key, runs on today's node with no fork: on a devnet and on public testnet, as a prototype, not something to use yet. Section 5 above listed this construction as unimplemented. Details, numbers and limits follow; nothing is asked of holders.

**The box.** A box commits to 16 WOTS keys as the AVL digest of their commitments in its script (33 bytes at any count; the count itself is also a script constant) and carries its index in R4, read as 0 when absent, so a plain payment to the address funds a usable box. A spend names a leaf at or above the box's index and supplies that leaf's signature and lookup proof; until the final leaf it must recreate the box with an index above the leaf it used. The verifier is section 2's, reading the commitment from the tree instead of a constant; the index and lookup checks come first in the `&&`, so a bad index is refused before any hashing.

**Executed.** On a devnet (ergo 6.0.6, block version 4): a forged signature rejected at 37,916 cost units; a spend that does not advance the index rejected at 52; leaf 0 signed again against the box reading 1, and leaf 0 named explicitly against it, both rejected at 28; a spend skipping to leaf 3 accepted (index to 4); a second plainly funded box at the same address spent with the wallet's next leaf, 4; every accepted spend confirmed. On public testnet, through a public testnet node (ergo 6.0.1, block version 4) from a box funded by a plain payment with no register: the same six verdicts (forged 37,854; unadvanced index 52; stale and named past leaf 28; leaf 0 then leaf 3 confirmed, the index reading 1 then 4; transactions `e9d0108c…` and `118c911e…`, the box at index 4 left unspent). The hybrid `proveDlog(owner) && (this lock)` ran on the devnet: a valid hash signature with no curve proof is rejected, both proofs confirm; the box grows 39 bytes and the spend 95 (the Schnorr proof), the cost difference inside the message-dependent variation of the hash verifier.

**Numbers, per spend** (derived from the printed figures). Script cost 37,644 to 37,876 units for the devnet's valid spends against 37,592 for the one-time box on the same devnet, the difference inside message variation; 3,477 bytes against 2,340, because the recreated 977-byte box rides along with the signature and proof; per mainnet block about 156 by cost (8,001,091 ÷ (13,301 + cost)) and 365 by size (1,271,009 ÷ 3,477), against 158 and 542 for the one-time box, where the post's 154 used the harness worst case and 158 the measured cost. A forged signature still costs the node the full verification and pays no fee, as for the one-time box. Rent on the box that persists: about 1.22 ERG per four years at the current factor (977 bytes × 1,250,000 nanoERG), and the rent clock resets on every spend.

**What the chain enforces, and what it does not.** Per box: the index never moves backwards, and a leaf below it cannot spend. So a wallet restored from an old backup that signs a leaf the box has moved past exposes a leaf that can no longer spend that box. What the chain cannot do is stop a signer from signing the current leaf twice off chain; two signatures from one leaf, both public, are the forgery window. The wallet therefore keeps one counter per key set, never decremented, and uses a fresh leaf for any replacement, which the "at or above" rule allows: a stuck spend is replaced by signing the next leaf, never the same one again. Not shown: hiding which leaf signed (R4 and the proof name it, and the proof's sibling hashes are public; they reveal nothing about unused leaves' secrets, by reading, not by test); binding of other inputs (the message covers SELF.id and the outputs, as in section 2); heights above 4 or the last-leaf branch (not run); adding leaves (the tree is built off chain and read-only).

**Prior work.** QRL has enforced one-time use of XMSS indices at consensus since 2018, as a protocol rule for its one scheme and address type. WOTS-Tree (Mateos, ePrint 2026/374) brings XMSS to Bitcoin with up to 2^21 leaves and recovers the index by scanning the chain, the signer enforcing it; Kudinov and Nick (2025/2203) prefer stateless schemes for Bitcoin because of the state-rollback failure, while keeping the stateful option open; BPQS (2018/658) chains two-leaf trees with signer-side state. What is added here is the same enforcement as a box script on a chain whose protocol knows nothing about the scheme. The search scope is in the repository's prior-art note; it did not cover the Bitcoin mailing lists or IOTA.

**How many leaves.** Over 791,286 mainnet blocks (789,437 contiguous from genesis plus a few near the tip; the 2019 to 2022 era, 42% of today's height), 263,160 P2PK keys signed at least one input; by inputs signed, which is leaves consumed when each box is a lineage: median 2, 40.7% exactly once, 99.6% at most 1,024, 0.37% above 1,024 (the largest count 138,346; who they are is not measured) with a third of all inputs between them. Repository `q3/`, aggregates only; the scanner runs on a stopped node's history store in one command.
