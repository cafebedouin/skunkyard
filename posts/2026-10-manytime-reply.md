Prepared with Claude Code (Anthropic, Claude Fable 5.1) for cafebedouin using peeryard v0.1.0 (ba56b25) on 6.0.6 (21b9023933b1); executed on a devnet and on public testnet, recorded in the skunkyard project.

Section 5 listed the many-time construction as unimplemented. It is implemented and run, on a devnet and on public testnet (skunkyard, `skunks/manytime/`).

**The box.** A box commits to 16 WOTS keys as the AVL digest of their commitments in its script (33 bytes at any count) and carries the next leaf index in R4. A spend supplies the leaf's signature and its lookup proof and, until the final leaf, must recreate the box with the index advanced; the verifier is section 2's, reading the commitment from the tree instead of a constant. The state check and the lookup run before the signature verification.

**On a devnet** (ergo 6.0.6, block version 4): a forged signature rejected (37,860 cost units); a spend leaving the index unchanged rejected at 38; leaf 0 replayed against the box reading index 1 rejected (the lookup fails for the key the script computes; an evaluation exception, so the node reports no cost); two consecutive spends confirmed with the index reading 1, then 2. **On public testnet** through a node we do not run (the Cornell testnet node, ergo 6.0.1): the same five outcomes, forged at 37,997, wrong index at 38, spends `8185de6d…` and `1634f45e…` confirmed, the box carrying index 2 left unspent. **The hybrid** `proveDlog(owner) && (this lock)` also ran on the devnet: a valid hash signature with no curve proof is rejected, both proofs confirm, at about 500 units and 95 bytes over the hash lock alone.

**Numbers, per spend.** 37,550 to 37,860 cost units against 37,592 for the one-time box; 3,450 bytes against 2,345 (the recreated 953-byte box rides along with the signature and proof); per mainnet block 156 by cost and 368 by size, against 158 and 542. Storage rent on the box that persists: 953 bytes, about 1.19 ERG per four years at today's factor.

**What it changes.** The index is enforced by the chain on every spend but the last: a spend that does not advance it, or that reuses a leaf the box has moved past, is rejected by the node, including the case the literature rejects stateful schemes for, a wallet restored from an old backup. The wallet keeps one rule: never sign a leaf twice, since the index advances only on confirmation; a stuck spend is replaced by spending the output, not by re-signing. Not shown: hiding which leaf signed (R4 and the proof name it; unused commitments stay inside the digest, and a used leaf's signature and proof reveal nothing about unused leaves); binding of other inputs (the message covers SELF.id and the outputs, as in section 2); adding leaves (the tree is built off chain and read-only).

**Prior work.** The closest is WOTS-Tree (Mateos, ePrint 2026/374), XMSS parameterized for Bitcoin with up to 2^21 leaves, where the index is recovered by scanning the chain but enforced by the signer; Kudinov and Nick (2025/2203) decline stateful schemes for Bitcoin because of exactly the state-rollback failure; BPQS (2018/658) chains two-leaf trees with signer-side state. None has a script reject reuse, which Bitcoin's script cannot express and Ergo's can. Two of their refinements apply here and are queued: 128-bit chains with 256-bit tree nodes (about 560-byte signatures, security caveat to be stated) and seed-derived leaves.

**How many leaves.** Over the first 791,286 mainnet blocks, 263,160 P2PK keys ever signed; the median signed twice and 47% once; 99.6% signed fewer than 1,024 inputs; the 0.37% above that (pools, exchanges, scripts; maximum 138,346) account for a third of all signings (`q3/RESULT.md`, aggregates only, scanner included). [SAMPLE LINE] So h = 10 covers nearly every holder and the rest need h = 20 or rotation at the last leaf, which is a wallet setting, since the chain sees only the digest.

**Two notes on the summary above**, for a reader checking it against the tables. The capacity line, "about 154 against 596, 3.9x", is the cost bound for one input; the size bound in section 3's table is 542 against 4,367, and a native opcode does not move it, since the signature stays in the transaction. Storage rent falls on a box unspent for 1,051,200 blocks: an 866-byte WOTS box reaching that age pays about 1.08 ERG per period at today's factor, against about 0.13 for a P2PK box, and the census's oldest exposed bucket (older than 525,600 blocks at height 753,934: 9.16M ERG in 29,795 boxes, `q1/RESULT.md`) is the cohort that reaches that age first. "Nothing to do today" in section 6 is about action, not about what a lock costs to hold.
